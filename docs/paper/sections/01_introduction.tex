\section{Introduction}
\label{sec:intro}

A \emph{succinct argument for machine execution} convinces a verifier that a program, run on a given instruction-set architecture, produced a given output, with a proof far shorter and a check far cheaper than the execution. Such systems are commonly called zero-knowledge virtual machines (\zkVM{}s), although the execution proofs studied here are succinct but not hiding; an optional terminal proof adds hiding (\S\ref{sec:zk}). The \emph{arithmetisation} of a \zkVM{} turns an execution into tables whose rows satisfy polynomial constraints and between which multiset relations hold, and determines the trace cells and bus interactions per instruction; its \emph{commitment} and proximity test let the prover show that it knows such tables, and determine the cost of encoding, hashing and opening those cells. The benchmark throughout is an Ethereum block of several hundred million instructions~\citep{ethproofs}, a hash-intensive workload.

\paragraph{Motivation.} \Ziren{} is a \zkVM{} for MIPS32. It proves 77 user-mode integer instructions of MIPS32r2 with the branch-delay slot (Appendix~\ref{sec:app-isa}) and has proved Ethereum mainnet blocks end to end; earlier proof systems address MIPS-\emph{like} models or offer MIPS as one mode among several (\S\ref{sec:related}). The instruction set is stable, its owner having moved its roadmap to RISC-V in 2021~\citep{mips-riscv-2021,mips-at-40}; its fixed 32-bit encodings in a handful of formats let one row carry an instruction's whole frame; and Rust, Go and C programs compile to the same little-endian ELF for a widely deployed architecture~\citep{mips-shipped}. The fault-proof software of Ethereum rollups, Optimism's Cannon and Kona~\citep{cannon,kona}, can therefore be targeted, subject to compatible runtime conventions and image formats, and on constrained devices, where proofs today serve authentication and attestation~\citep{zk-iot-survey,zpie,zekra,zra}, the software execution of the device can become the statement.

\paragraph{Challenges.} Four properties shape the design. The instruction after a branch executes before control transfers, whether or not the branch is taken~\citep{mips32-isa}, so the next instruction address must be carried as machine state rather than inferred as $\mathsf{pc}+4$. The relations that hold the machine together are multiset relations \emph{across} tables, so discharging them table by table would cost one argument per bus per table. A shard of the block workload commits up to about $3.6\cdot10^4$ columns whose heights run from 32 rows to millions: separate commitments require many Merkle roots and authentication paths, and a common height wastes space on padding. And a 32-bit word does not fit the 31-bit field, so every word is a vector of bytes.

\subsection{Overview of Ziren}
\label{sec:intro-approach}

\Ziren{} represents each executed instruction by one row of an opcode-specific trace table (a \emph{chip}), with no central CPU table. Each chip embeds an \emph{instruction frame}: shared columns and bus interactions that bind the instruction to the committed program, place its register accesses at fixed sub-cycle positions and constrain the machine-state transition. The state includes both the current and the next program counter, which preserves the branch-delay slot (\S\ref{sec:air-frame}). The committed trace is thus the execution regrouped by opcode, with the state bus as its permutation check.

One shard proof covers the chip rows and their bus interactions. Registers and memory share one offline memory-checking argument, carried across shards by an elliptic-curve digest; one \LogUp{} instance checks all bus balances and one zerocheck all chip constraints; and the jagged sumcheck of Hemo et al.~\citep{jagged-pcs} reduces the claims on tens of thousands of columns of differing heights to one evaluation, which a single batched \WHIR{} opening~\citep{whir} authenticates against every commitment. A \emph{univariate skip} replaces the first four rounds of the zerocheck, those over the largest tables, and the folds between them by one round over a sixteen-point domain and a single fold (\S\ref{sec:air-skip}). Recursion composes the shard proofs under a verifying-key allowlist into one \emph{compressed proof}, so a block proof is
\[
  \mathsf{Rec}\Big[\,\mathsf{FS}\big[\,\mathsf{JaggedWHIR}\big[\,\mathsf{LogUpGKR} \wedge \mathsf{Zerocheck}\,\big[\mathcal R_{\mathrm{shard}}\big]\big]\big]\Big]
\]
(Figure~\ref{fig:architecture}, Section~\ref{sec:architecture}). After the recursion root, an optional \emph{zero-knowledge terminal proof} adds one hiding proof (\S\ref{sec:zk}); SNARK wrapping for on-chain verification and garbled verification are the other terminal routes (\S\ref{sec:applications}).

\paragraph{Contributions.} The commitment scheme, proximity test, lookup argument and recursion shape \Ziren{} builds on are prior work, used as published. The paper contributes the following.
\begin{itemize}
\item \emph{The machine and its argument.} An arithmetisation of MIPS32 with no CPU table, in which an instruction frame carries the delay slot as a program-counter pair (Sections~\ref{sec:isa} and~\ref{sec:air}); the concrete composition of the jagged reduction with \WHIR{}, with its multi-root layout, parameter schedule and recursive verifier (Sections~\ref{sec:pcs} and~\ref{sec:iopp}); and a univariate-skip form of the shard zerocheck, with the row weights it induces in the jagged reduction and its round error (\S\S\ref{sec:air-skip} and~\ref{sec:pcs-skip}).
\item \emph{A zero-knowledge terminal proof.} An optional hiding proof after the recursion root, built from committed random rows, masked sumchecks and a hiding variant of the \WHIR{} opening (\S\ref{sec:zk}).
\item \emph{Determinism in \Lean{}.} The determinism of each of the 57 chips the extraction models is stated as a \Lean{} theorem, extracted mechanically from the constraint description the prover evaluates, and proved by replaying a propagation analysis over a library of hand-proved gadget lemmas (\S\ref{sec:verification}). All \ndettotal{} theorems are closed, with no axiom beyond \Lean{}'s standard three.
\item \emph{Cost model.} Instruction efficiency in committed trace cells and bus interactions per guest instruction, separated from hardware-dependent proving throughput, and the relation of the final proof size to proving cost through the query count, code rate, folding schedule and grinding budget (\S\ref{sec:intro-costs} and Section~\ref{sec:performance}).
\end{itemize}

\paragraph{One instruction, one row.}\label{sec:techniques} A MIPS32 \texttt{and} executed at clock $\mathsf{clk}$ occupies one row of the bitwise chip, 37 columns wide: thirty columns of instruction frame (\S\ref{sec:air-cost}), the program-counter pair, four selectors and a gate. Through the frame, the row sends $(\mathsf{pc}, \mathsf{opcode}, \ldots)$ on the program bus, receives $(\mathsf{shard}, \mathsf{clk}, \mathsf{pc}, \mathsf{next\_pc})$ and sends $(\mathsf{shard}, \mathsf{clk}+5, \mathsf{next\_pc}, \mathsf{next\_pc}+4)$ on the state bus, and performs its three register accesses on the memory bus. No polynomial constraint computes the result: four lookups into a $2^{16}$-entry byte table establish it (\S\ref{sec:air-bytes}).

\subsection{Costs}
\label{sec:intro-costs}

\paragraph{Cost model.} \Ziren{} commits Merkle trees over Reed--Solomon encodings of a 31-bit field, where every cell costs the same whatever it holds, unlike under a commitment built from multi-scalar multiplication, where small values are cheaper~\citep{jolt}. The units of prover work are therefore trace cells and bus interactions. For an execution with guest-instruction count $C$, trace area $A$ and $I$ (row, interaction) pairs (\S\ref{sec:prelim-chips}), proved in $T$ seconds under the measurement boundary of \S\ref{sec:perf-setup}, we report
\[
  \text{instruction efficiency} = (A/C,\ I/C),
  \qquad
  \text{proving throughput} = \frac{C}{10^6 T}\;\mathrm{MHz}.
\]
For a fixed workload and sharding rule, the first pair describes the arithmetisation independently of the hardware. The model counts the frame and the opcode logic separately, includes shard-boundary memory rows, and charges the multiple accelerator rows generated by a single precompile call.

\paragraph{Prover costs.} An executed instruction pays for its frame before it computes anything (\S\ref{sec:air-cost}), and the operation adds from four columns (addition) to over a hundred (division) among the arithmetic chips (\S\S\ref{sec:base} and~\ref{sec:ext}); block 25\,955\,640 commits about 59 cells and raises about 26 bus interactions per executed instruction. A precompile call is one guest cycle but many rows, and a shard closes on its committed area, so guest cycles do not measure prover work (\S\ref{sec:perf-estimate}). On the 15 consecutive Ethereum mainnet blocks of Table~\ref{tab:clients}, warm proofs with Reth and Geth reach $12.0$\,MHz on one NVIDIA RTX~5090 and $75.8$\,MHz on eight, and the Reth guest, at lower throughput, proves each block $1.8$--$3.9$ times faster than Geth on one GPU.

\paragraph{Verifier costs.} The compressed proof is 284\,KiB and its native verification takes a median of 31.4\,ms on the evaluation host, with the in-circuit child-key allowlist checks enabled (\S\ref{sec:perf-proofsize}). For a fixed root verifier program, the size is independent of the execution's length and is set by the opening's schedule. Every proof stage has more than 100 bits of interactive soundness, and the \emph{composite security} of a block, $-\log_2$ of the sum of the interactive error bounds over all tree nodes, is $93.5$ bits for a tree with 149 core-schedule proofs and one compress root. These figures bound the \emph{interactive} protocol; \S\ref{sec:iopp-soundness} gives the union-bound accounting and the level after Fiat--Shamir compilation.

\subsection{Security statement}
\label{sec:intro-audit}

An accepting proof implies a satisfying trace; that the trace is an execution of the advertised machine needs the arithmetisation to admit one behaviour per input, which the proof system cannot establish about itself. Security is therefore stated in two parts. First, honest executions that halt with exit code zero produce accepting proofs (\S\ref{sec:statement}), and the recursion tree is knowledge sound for its satisfying witness rows in the random-oracle model, with the conditional error bound of Theorem~\ref{thm:composition}. The conditions are that every node's protocol is round-by-round knowledge sound, that child extractors accept the transcripts produced by parent extractors, that the recursion programs enforce the compose relation, and that Assumption~\ref{ass:digest} on the cross-shard digest holds (\S\ref{sec:iopp-layers}). Second, identifying those rows with a unique execution of the MIPS32 relation of Section~\ref{sec:isa} requires the premises of Theorem~\ref{thm:unique}: chip determinism, well-formed shard boundary rows and real-row exhaustiveness (\S\ref{sec:security-relation}). Chip determinism is machine-checked: for every chip of the core machine that the extraction models, a mechanically extracted \Lean{} theorem states that two rows that satisfy its constraints and agree on their inputs (their bus inputs and the values the constraints leave to the prover by design) agree on their bus outputs, and all \ndettotal{} such theorems are closed (\S\ref{sec:verification}). The other two premises are argued, not proved.

\subsection{Related work}
\label{sec:related}

The comparisons below are of design; no cross-system performance claim follows from them.

\paragraph{Arithmetisation and memory.} SP1~\citep{sp1,sp1-hypercube} and OpenVM~\citep{openvm} also prove RISC-V execution in per-opcode chips without a CPU table. The instruction frame supplies, for MIPS32 and its delay slot, the state transitions and register accesses that SP1 implements with state-and-reader columns and OpenVM with adapters (\S\ref{sec:air-frame}), and we use SP1's elliptic-curve cross-shard digest~\citep{sp1-turbo-memo} and register shadow read. Jolt~\citep{jolt,twist-shout} evaluates instructions by lookups; \Ziren{} uses per-opcode constraints and keeps lookups for byte-granular facts and buses, its byte table being the original Jolt design's decomposition of an instruction table (\S\ref{sec:air-bytes}). The regrouping by opcode is the device of vRAM~\citep{vram}, which Ceno published in multiset form~\citep{ceno,ceno-repo}, and the memory check is Blum et al.'s offline check~\citep{blum1994} with Spice's timestamps~\citep{spice}, which does not reorder the trace (\S\ref{sec:prelim-lookups}). ZisK~\citep{zisk} lowers execution to micro-operations, Airbender~\citep{airbender} and RISC Zero~\citep{risc0} constrain one trace of machine cycles, and Cairo~\citep{cairo} and Valida~\citep{valida} design an instruction set for proving rather than inherit a hardware one. Among MIPS systems, Zilch's zMIPS verifies a MIPS-like instruction model~\citep{zilch}, o1VM documents a segmented prover with MIPS and RISC-V modes~\citep{o1vm}, and Cannon~\citep{cannon} is a single-step MIPS interpreter for interactive fault proofs, whose test programs we use for conformance.

\paragraph{Commitment, soundness and verification.} The jagged commitment is that of Hemo et al.~\citep{jagged-pcs}, who anticipate \WHIR{} in place of their FRI-based opening~\citep[Rem.~7.1]{jagged-pcs}; our contribution is the concrete composition and its soundness accounting. The query analysis uses unique decoding below the root and the Johnson bound at the root, both with proved bounds, and component errors are summed (\S\ref{sec:iopp-soundness}). SP1 Hypercube opens with BaseFold~\citep{basefold} under unique decoding with proved proximity-gap bounds~\citep{sp1-security}. OpenVM's SWIRL combines stacked \WHIR{} with \LogUp{}~\citep{swirl}, but pads columns to power-of-two heights with a univariate skip, reduces openings by a batch sumcheck fused with the lookup's input layer, and composes round-by-round errors by their maximum per layer; \Ziren{} rounds heights to a multiple of 32, uses the jagged sumcheck, and confines its univariate skip to the four lowest row variables of the zerocheck. Picus~\citep{picus} introduced the determinism formulation and an SMT solver for it; we discharge it in \Lean{}, which gives kernel-checked proofs. OpenVM's verification project proves refinement of its RV32IM and precompile chips to Lean specifications~\citep{openvm-fv}, a stronger property than determinism, for a different ISA.

\subsection{Scope and limitations}
\label{sec:scope}

The evaluation and the security accounting cover \Ziren{} through the compressed proof; the zero-knowledge terminal proof is treated in \S\ref{sec:zk}, and the applications built on these proofs (\S\ref{sec:applications}) are outside the scope. Soundness rests on a computational assumption for the cross-shard digest in addition to the information-theoretic bounds of the proximity test, and that assumption, unlike the rest of the argument, does not survive a quantum adversary (\S\ref{sec:pq}). The determinism proofs cover the core machine except its two SHA-256 control chips, and not the recursion machine; Theorem~\ref{thm:unique} itself is argued on paper. The evaluation uses one workload class on one GPU model. The verifying-key allowlist is enumerated from the machine's declared chip-set clusters, which are curated from its target workloads rather than exhaustive, so a shard outside them is refused rather than admitted (\S\ref{sec:argument-block}).
