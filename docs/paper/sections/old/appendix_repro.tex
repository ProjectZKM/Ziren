\section{Reproducibility}
\label{sec:repro}
\sloppy

\paragraph{Software revisions.} All measurements and verification results refer to the \Ziren{} repository at \url{https://github.com/ProjectZKM/Ziren}, branch \texttt{feat/upgrade-plonky3}. The deployed schedule of Table~\ref{tab:levers} is revision \texttt{7fe33b11} (the \WHIR{} schedule of Section~\ref{sec:iopp-schedule}) with \texttt{22efae5a} (no lookup grinding); the three changes of Table~\ref{tab:levers} are \texttt{c623cefd}; the lookup-circuit layer pairing of Section~\ref{sec:perf-after} is \texttt{49977616}; the conformance suite and the \Lean{} project are on branch \texttt{spec/mips-vectors} at \texttt{ad4e252c} and \texttt{e36004dc} (crates \texttt{core/executor/tests/spec\_vectors}, \texttt{core/machine/tests/spec\_vectors\_prove}, \texttt{picus}, directory \texttt{lean/ZirenDet}). The GPU kernels are the \texttt{ziren-gpu} repository at \texttt{464d567} (census and three changes) and \texttt{48d6cce} (after). The soundness configuration and the \texttt{soundcalc} report are in \texttt{docs/soundness/} (\texttt{ziren.soundcalc.toml}, \texttt{ziren.soundcalc-report.md}); the union bound of Section~\ref{sec:iopp-soundness} is computed from the per-component bits in that report.

\paragraph{Guest.} The workload is mainnet block 25\,907\,955 executed by a MIPS32r2 build of \texttt{reth} (repository \texttt{reth-processor}, revision \texttt{2336fbc}: arena witness trie, word-wise \texttt{memcmp}, zero-copy Keccak), 288\,million cycles; the input witness file is cached and reused, so every run executes the identical instruction stream. Cycle counts are produced by the executor with \texttt{ZKM\_DUMP}; the area census by the executor's shard-close census (\texttt{ZIREN\_SHARD\_CLOSE\_CENSUS}) multiplied by the chip widths of Table~\ref{tab:chips}; the kernel split by \texttt{nsys} over a ten-shard sample.

\paragraph{Hardware and software environment.} One NVIDIA RTX~5090 (32\,GB GDDR7, driver 570.153.02, CUDA 12.8) in a host with one AMD EPYC 9355 (124 hardware threads visible to the prover), 925\,GB of RAM, Ubuntu 22.04.4, Linux 5.15; the prover process is pinned to one GPU with \texttt{CUDA\_VISIBLE\_DEVICES}, and a second production process on another GPU of the same host was running during the measurements, so the CPU was not idle. The multi-GPU figures of Section~\ref{sec:perf-after} use GPUs 4--7 of the same host. Rust nightly-2026-07-17; the guest is built with the \Ziren{} MIPS toolchain (\texttt{rust-toolchain-20260108}).

\paragraph{Measurement protocol.} Each configuration pair is measured in interleaved A/B/B/A order on the same GPU and the same block, with the medians reported; the per-arm spread over three repetitions was within $\pm 1$\,s of the median for every row of Table~\ref{tab:levers} and within $\pm 0.8$\,s for Table~\ref{tab:cards}. ``Wall'' is the end-to-end time of the process from reading the cached input to writing the verified compressed proof, including host verification of every shard proof and of the compressed proof (about 2--3\,s of the total, which a production service would omit). Proof sizes are the byte length of the serialised compressed proof.

\paragraph{Verification artifacts.} The conformance suite is an integration test of the executor crate that runs the specification-derived vectors and the Cannon programs against the reference results, and a second integration test of the machine crate that proves a configurable number of them end to end; the vectors and their decoded forms are stored next to the tests and regenerated by a generator script from the encoding tables using Unicorn 2 and the LLVM 18 assembler. The \Lean{} project (\Lean{} 4.33.1, Mathlib at the pinned revision of its manifest) contains the ISA model, the two model checks (decoder agreement and vector replay), one generated file per unit with the extracted determinism theorems, and the hand-maintained tactic library; it is built with the standard Lake build, and the generated files are produced by the extraction crate from the same constraint description the prover evaluates.
