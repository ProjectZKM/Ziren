\section{The guest instruction set}
\label{sec:app-isa}

A guest may execute 77 MIPS32r2 user-mode integer instructions, the set the relation of \S\ref{sec:statement} quantifies over and the set from which the conformance corpus of \S\ref{sec:verification-conformance} is generated. Table~\ref{tab:chips} lists them by family with the chip that proves each, which fixes the instruction chips a program can occupy and with them the chip sets that Section~\ref{sec:argument-block} enumerates over. The four moves to and from \texttt{LO} and \texttt{HI} are additions of an immediate zero (\S\ref{sec:isa}), and \texttt{sync}, \texttt{synci} and \texttt{pref} are accepted and retire as no-ops, proved as an addition of zero. \texttt{syscall} is not counted among the 77: it is the boundary of the machine rather than a computation within it (\S\ref{sec:ext-syscall}). The other MIPS32r2 user-mode integer instructions (the conditional traps other than \texttt{teq}, the linking conditional branches \texttt{bgezal} and \texttt{bltzal}, the branch-likely forms, \texttt{break} and \texttt{rdhwr}) are not supported: they decode to an unimplemented opcode and execution stops with an error.

\paragraph{System calls.} The behaviour of every call number is fixed; none is left unconstrained. The machine accepts accelerator calls, received by the precompile chips of Table~\ref{tab:chips-other}; ten local calls that the system-call chip proves in its own row (halt, commit, hint and proof-verification calls); and Linux calls. Seven Linux calls, under eight numbers, have their semantics: \texttt{brk}, \texttt{read}, \texttt{write}, \texttt{exit\_group}, \texttt{mmap}/\texttt{mmap2}, \texttt{clone} and \texttt{fcntl}. Seventeen more, the ones a standard runtime issues while starting, are accepted as no-ops: \texttt{open}, \texttt{openat}, \texttt{close}, \texttt{fstat64}, \texttt{clock\_gettime}, \texttt{nanosleep}, \texttt{futex}, \texttt{prctl}, \texttt{uname}, \texttt{prlimit64}, \texttt{sigaltstack}, \texttt{rt\_sigaction}, \texttt{rt\_sigprocmask}, \texttt{madvise}, \texttt{munmap}, \texttt{gettid} and \texttt{sched\_getaffinity}. A no-op call touches no memory and returns $0$ with the error flag clear. That is deterministic, since the machine's memory is fully defined, but it is not the ABI's meaning: a program that reads a time, a file or an affinity mask through one of them gets no value, and must not depend on one. Any other call number stops the execution with an error before any state changes, so the relation rejects and the honest prover produces no proof.

The circuit pins the same outcomes and accepts the same numbers. The Linux-call chip decodes each of the eight implemented and seventeen no-op numbers and requires a real row to carry one of them, and the system-call chip requires a call it does not send to a table to be one of its ten local calls. A row carrying any other number has no satisfying assignment, so a proof states only an execution $\mathsf{Emulate}$ performs. The enumeration costs the two chips 11 and 35 columns.
