\section{Conclusion}
\label{sec:conclusion}

We have presented \Ziren{}, a succinct argument for MIPS32 execution. Its architecture is one proving stack whose compressed proof a native verifier checks, with two applications built on it for on-chain and garbled verifiers (Section~\ref{sec:architecture}). One row of one chip per executed instruction, carried by an instruction frame, replaces the CPU table; one lookup argument, one zerocheck and one jagged \WHIR{} opening prove each shard; and a recursion tree with an enumerated key allowlist composes the shards into one proof. Conformance suites and an executable \Lean{} model test the emulator. Determinism is extracted from the constraint description the prover evaluates; all \ndettotal{} extracted theorems are closed in \Lean{}, and the statements exposed three soundness gaps that the constraints now close.

Beyond determinism, two techniques surround the machine. Proving is pipelined, so what remains serial is the start-up interval and the recursion tail (\S\ref{sec:perf-pipeline}). And cross-shard memory has four options: an elliptic-curve multiset hash, the one component that is not hash-based; a lattice multiset hash; a global challenge; and Merkle roots over touched memory (\S\S\ref{sec:air-global} and~\ref{sec:pq}, Table~\ref{tab:pq}).

The performance study identifies trace area, lookup interactions, layer order and shard size as distinct cost levers. The two largest costs it identifies are the lookup argument, 42\% of kernel time, and the cross-shard digest, 15\% of the block's area, which a digest of per-shard deltas or a larger shard would reduce. The open proof obligations are the five hypotheses of \S\ref{sec:security-relation}; future work should measure the corrected $\Poseidon{}$ schedule against one configuration, soundness report, key set and proof.
