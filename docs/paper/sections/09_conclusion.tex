\section{Conclusion}
\label{sec:conclusion}

We have presented \Ziren{}, a succinct argument for MIPS32 execution. Its architecture is one proving stack whose compressed proof a native verifier checks, with SNARK wrapping and garbled verification as routes to EVM-compatible rollups, private computation and Bitcoin rollups (Section~\ref{sec:architecture}). One row of one chip per executed instruction, carried by an instruction frame, replaces the CPU table; one lookup argument, one zerocheck and one jagged \WHIR{} opening prove each shard; and a recursion tree with an enumerated key allowlist composes the shards into one proof. Conformance suites and an executable \Lean{} model test the emulator. Determinism is extracted from the constraint description the prover evaluates; all \ndettotal{} extracted theorems are closed in \Lean{}, and the statements exposed three soundness gaps that the constraints now close.

The cost model expresses instruction efficiency in trace cells and bus interactions per guest instruction, separately from hardware-dependent proving throughput (\S\ref{sec:intro-costs}). It accounts for instruction-frame overhead, shard-boundary memory rows and precompile expansion, which explain why guest-instruction counts alone do not measure prover work.

The performance study identifies trace area, lookup interactions, layer order and shard size as distinct factors in proving cost. The two largest costs it identifies are the lookup argument, 42\% of kernel time, and the cross-shard digest, 15\% of the block's area, which a digest of per-shard deltas or a larger shard would reduce. The open proof obligations are the five hypotheses of \S\ref{sec:security-relation}; future work should measure the corrected $\Poseidon{}$ schedule against one configuration, soundness report, key set and proof.
