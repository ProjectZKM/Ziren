\section{MIPS32 and the execution relation}
\label{sec:isa}

This section states the relation \Ziren{} proves; the machine's specification is the architecture manual~\citep{mips32-isa}. The guest has no floating-point unit, privileged state or interrupts; it executes the 77 instructions of Appendix~\ref{sec:app-isa} and reaches the outside world only through system calls.

\begin{definition}[Machine state]
\label{def:state}
The machine state is $(\mathsf{pc}, \mathsf{next\_pc}, R, M)$. $R$ holds 32 general registers of 32 bits, register 0 reading as zero, together with the \texttt{HI}/\texttt{LO} pair written by multiplication and division; $M$ is a little-endian, byte-addressed memory over a 32-bit address space. $\mathsf{pc}$ is the address of the instruction about to execute and $\mathsf{next\_pc}$ the address of the one that executes after it, which is not in general $\mathsf{pc}+4$.
\end{definition}

\begin{definition}[Instruction format]
\label{def:format}
Every instruction of the guest is decoded, once and before proving, into a tuple $(\mathsf{opcode}, \mathsf{op\_a}, \mathsf{op\_b}, \mathsf{op\_c}, \mathsf{imm\_b}, \mathsf{imm\_c})$. $\mathsf{op\_a}$ is the index of the register the instruction writes (or, for a store or branch, reads); $\mathsf{op\_b}$ and $\mathsf{op\_c}$ are each either a register index or an immediate already sign- or zero-extended to 32 bits, as the flags $\mathsf{imm\_b}$ and $\mathsf{imm\_c}$ say.
\end{definition}

The decoded form abstracts MIPS32's three encodings as Jolt's five-tuple abstracts RISC-V's~\citep{jolt}: a register instruction becomes $(\mathit{rd}, \mathit{rs}, \mathit{rt})$, an immediate instruction, load or store $(\mathit{rt}, \mathit{rs}, \mathrm{ext}(\mathit{imm}))$, and a branch $(\mathit{rs}, \mathit{rt}, \mathrm{sext}(\mathit{off}) \ll 2)$. The decoded image is the preprocessed \emph{program table}, keyed by address and committed into the verifying key (\S\ref{sec:statement}). \texttt{LO} and \texttt{HI} are registers 32 and 33, so a move between them and a general register is an addition of zero; with two slots used by the memory-management system calls there are 36 register slots.

\begin{definition}[Step]
\label{def:step}
From a state $(\mathsf{pc}, \mathsf{next\_pc}, R, M)$, decode the word at $\mathsf{pc}$ as in Definition~\ref{def:format}, let $b$ and $c$ be the operands $\mathsf{op\_b}$ and $\mathsf{op\_c}$, read from $R$ unless immediate, and let $a = R[\mathsf{op\_a}]$. $\mathsf{Step}$ executes the instruction by family:
\begin{itemize}
  \item an arithmetic, logical, shift, bit-field or move instruction sets $R[\mathsf{op\_a}] \gets f_{\mathsf{opcode}}(a, b, c)$, and multiplication and division also set \texttt{HI};
  \item a load sets $R[\mathsf{op\_a}]$ to the selected bytes of $M[b + c]$, extended, and a store merges the selected bytes of $a$ into $M[b + c]$;
  \item a branch or jump computes a target $t$ ($b$, $\mathsf{next\_pc} + b$ or $\mathsf{next\_pc} + c$) and a condition $\mathit{taken}$ on $a$ and $b$, true for a jump, and a linking jump sets $R[\mathsf{op\_a}] \gets \mathsf{next\_pc} + 4$;
  \item a system call performs the call of \S\ref{sec:ext-syscall}, which may halt.
\end{itemize}
It then sets $R[0] \gets 0$ and returns $(\mathsf{next\_pc}, \mathsf{next\_next\_pc}, R', M')$ with $\mathsf{next\_next\_pc} = t$ if $\mathit{taken}$ and $\mathsf{next\_pc} + 4$ otherwise. $\mathsf{Step}$ \emph{rejects} if the word does not decode, on a division by zero, on a \texttt{teq} with $a = b$, and on a call number the machine does not implement (Appendix~\ref{sec:app-isa}).
\end{definition}

The rule for the counter pair departs from RISC-V: a transfer sets the \emph{second} component of the counter pair, so the instruction in its \emph{delay slot} still executes and its successor is the branch target. Every row therefore witnesses $\mathsf{next\_pc}$, and the pair is architectural state that crosses every shard boundary (\S\ref{sec:argument-block}). A transfer in a delay slot, which the manual leaves unpredictable, gets the meaning the same rule gives it. In the arithmetisation the instruction frame performs the fetch, the operand reads, the register write and the advance, the memory argument the memory access, and a chip's own columns only the function $f$ (\S\S\ref{sec:base} and~\ref{sec:ext}).

\subsection{Clock and shards}
\label{sec:isa-record}

Execution is divided into \emph{shards}. Within a shard a clock $\mathsf{clk}$ advances by five per instruction, and by a bounded number more for a system call (\S\ref{sec:ext-syscall}). The accesses of an instruction executed at $\mathsf{clk}$ occupy five \emph{sub-cycle positions} $\mathsf{clk}+\mathsf{pos}$, one per role (\S\ref{sec:air-frame}), so $(\mathsf{shard}, \mathsf{clk} + \mathsf{pos})$ timestamps every access. Execution keeps the clock below a \emph{clock limit} of $2^{25}$, which caps a shard at about $6.71$\,M cycles; the range-checked clock limbs of the circuit (\S\ref{sec:air-frame}) prove it only below $2^{26}$, which still excludes wrap-around. A shard closes at the first limit reached: the clock limit, the configured shard size of a few million cycles, a chip's height budget, or a committed-area budget of $4.6\cdot10^{8}$ cells.

The value and timestamp of the first and last access to every word a shard touches are the leaves of the cross-shard memory argument (\S\ref{sec:air-global}), and the public values of Definition~\ref{def:shard} chain shards and recursion layers.

\subsection{The execution relation}
\label{sec:isa-emulator}

\begin{definition}[Execution]
\label{def:execution}
An \emph{execution} of a program image $P$ on streams $(\mathsf{in}, \mathsf{hint})$ is a sequence of machine states $\sigma_0, \sigma_1, \ldots, \sigma_T$ in which $\sigma_0$ is the state the image defines, with the counter pair $(\mathit{entry}, \mathit{entry}+4)$, the registers the image initialises and zero in the others, and the image's memory, $\sigma_{i+1} = \mathsf{Step}(\sigma_i)$ for every $i < T$ (Definition~\ref{def:step}), no step rejects, and step $T$ is a halting system call with exit code $e$.
\end{definition}

Write $\mathsf{Emulate}(P, \mathsf{in}, \mathsf{hint}) = (\mathsf{out}, e)$ for the output stream and exit status of that execution. It is deterministic: no step reads host state other than the streams. Where the manual leaves room, or describes behaviour a single-threaded guest cannot observe, $\mathsf{Emulate}$ fixes a choice and the arithmetisation proves the same one: \texttt{add} and \texttt{addi} do not trap on signed overflow and behave as \texttt{addu} and \texttt{addiu}; \texttt{j} and \texttt{jal} take the region bits of the program counter as zero, which is exact for text below $2^{28}$; \texttt{ll} places no reservation and \texttt{sc} always succeeds. A trap, a division by zero or an unrecognised instruction ends the execution with an error, which is not a halt the relation admits, so such an execution has no proof.

Two executors realise the relation, an interpreter that produces the record of events the prover consumes and a just-in-time compiler that cuts a run into shards for it to replay; agreement on the tested corpus and the conformance evidence of \S\ref{sec:verification-conformance} connect them, without proving equivalence for every program.

\paragraph{Incompleteness of the arithmetisation.} The arithmetisation refuses some executions the relation admits, which costs completeness, never soundness~\citep[Note~1]{cairo}. An execution is cut into shards, never between a transfer and its delay slot. The only halt proved is exit code zero. A load or store must address memory above the 36 register slots, and every address and program counter must be a canonical field element, below $p$. And a shard whose chip set lies outside the machine's declared clusters has no admissible verifying key (\S\ref{sec:argument-block}).

\subsection{The statement being proved}
\label{sec:statement}

With $P$ a program image, $\mathsf{in}$ an input stream and $\mathsf{hint}$ a host-supplied \emph{hint} stream, \Ziren{} proves the relation
\[
  \mathcal R \;=\; \big\{ \big((\mathsf{vk},\ h),\ (P, \mathsf{in}, \mathsf{hint})\big) \;:\; \mathsf{vk} = \mathsf{Setup}(P) \ \wedge\ \exists\, \mathsf{out} :\ \mathsf{Emulate}(P, \mathsf{in}, \mathsf{hint}) = (\mathsf{out}, 0) \ \wedge\ h = H(\mathsf{out}) \big\},
\]
where $\mathsf{Setup}$ maps an image to its verifying key, a Merkle commitment to the program ROM and the preprocessed tables of Section~\ref{sec:air}, and $H$ is SHA-256 over the committed output. $(\mathsf{vk},h)$ is public, and $\mathsf{vk}$ binds the program image; $(\mathsf{in}, \mathsf{hint})$ is the witness and $P$ is fixed by $\mathsf{vk}$. The proofs up to the compressed proof are not blinded and do not hide the witness; the optional terminal proof of \S\ref{sec:zk} is zero knowledge. Only exit code zero is admitted, although $\mathsf{Emulate}$ accepts a non-zero exit (\S\ref{sec:isa-emulator}). Supported honest executions within the configured resource limits that halt with exit code zero produce accepting proofs; extraction of $(\mathsf{in},\mathsf{hint})$ is conditional on Theorem~\ref{thm:composition} and on the trace-to-execution premises of Theorem~\ref{thm:unique}.
