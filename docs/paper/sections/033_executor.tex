\section{The just-in-time executor}
\label{sec:executor}

Section~\ref{sec:isa-emulator} states that the execution relation is realised twice. This appendix gives the mechanism of the second realisation, a just-in-time compiler for Linux x86-64 hosts. Nothing in the protocol depends on it; a platform without it proves the same statements more slowly.

\paragraph{Two implementations, three jobs.}\label{sec:exec-roles} The interpreter implements every instruction, syscall and error path, and is the only implementation that emits the event record the prover consumes. The compiler serves the two jobs that dominate wall-clock time and need no events: running a guest for its output alone, and \emph{minimal-trace production}, in which the coordinator runs the guest to the end and emits per shard a descriptor holding the pre-access value of every word the shard reads, the register records at its boundary and the boundary itself. A worker re-executes its shard from that descriptor under the interpreter, so no event record crosses a process boundary and the event-emitting path stays the interpreter's.

\paragraph{Compilation and the program cache.}\label{sec:exec-transpile}\label{sec:exec-state}\label{sec:exec-accounting}\label{sec:exec-traps} Compilation is one pass per program: each guest instruction is lowered to native code with a jump table from guest program counters to native addresses, and the guest register file is held in host registers. The compiled code performs the interpreter's bookkeeping, stamping accesses at the same sub-cycle positions and charging the same shard budgets, so a compiled run fences shards where an interpreted run would. It implements no syscall and no error path: every syscall, trap, misaligned access and unmodelled form is a trap site that synchronises state into the interpreter, runs that instruction there and resumes. Compiled programs are cached under a key that hashes the entire instruction stream, since a guest that shares a prefix and a suffix with another must not run the other's code.

\paragraph{Evidence that the two agree.}\label{sec:exec-equivalence} None of the checks is a proof of equivalence for every program. Tests assert that the descriptors of a compiled run are byte-identical to an interpreted run's; the 770 specification vectors of \S\ref{sec:verification} run on both and against an independent emulator; and continuous integration compares digests of the emitted records across runs and implementations on the tested corpus.
