# Hand-written gadget proofs

A file `<Module>.lean` here is spliced by `zkm-picus --format lean` into the generated chip file
of that module, before its determinism theorem.  It proves

    theorem gadget_det (w w' : W) (hw : constraints w) (hw' : constraints w')
        (hin : inputs w = inputs w') : w.v… = w'.v… ∧ …

for the columns the analyser took from a gadget summary, and the replayed derivation uses it at
those steps.  The placeholders `%OPEN_W%`, `%OPEN_W'%`, `%OPEN_HW%`, `%OPEN_HW'%` are replaced
by the patterns that split the witnesses into fields `x…`, `y…` and the constraint sets into
conjuncts `c…`, `d…`.  `%PROJ_Cn%` and `%PROJ_Dn%` are replaced by the projection of conjunct
`n` out of `hw` and `hw'`, for a snippet that keeps both witnesses whole.

The snippets name constraints by index, so they follow the chip's AIR: regenerate them after
any change to it.  The generators named below (`tools/`) are not kept in the repository; they
are distributed with the archived snapshot of the checked files (`src/crates/fv/lean4/snippets/tools`).

- `CloClz_is_clz.lean` rests on `ZirenDet/LeadingOne.lean` and needs
  `--shrcarry-summary precise` (the default `abstract` summary has fewer conjuncts, so its
  `row_spec` names conjuncts that do not exist).
- `DivRem_is_*.lean` rest on `ZirenDet/DivRem.lean` and are produced by
  `tools/gen_divrem.py <split chip file> <1 signed | 0 unsigned> <out>`; `tools/mktest.py`
  builds a file that checks one snippet without the replayed derivation.
- `Global.lean` rests on `ZirenDet/Septic.lean` (the septic field `F[z]/(z⁷ + 2z − 8)`, its
  irreducibility certificates, square-root sign and chord addition); `row_spec` names conjuncts
  and reified variables by index, so regenerate it with `tools/gen_global/` (`README` there).

The field-operation, point and decompression snippets (`Bn254*`, `Bls12381*`, `Bls12831*`,
`Secp256k1*`, `Secp256r1*`, `Ed*`, `Uint256MulMod`, `*FpOpAssign_is_*`) are generated from the
chip files by `tools/gen_field.py`, `tools/gen_fpop.py`, `tools/gen_u256.py`,
`tools/gen_decompress.py`, `tools/gen_decompress_lex.py` and `tools/gen_eddecompress.py`.  At
0.5-9 MB each they are not kept here: `../check/regen_all.sh` generates every one from its chip's
module, its table naming the generator, module and arguments of each, and then the chip files.
- `EdDecompress.lean` rests on `ZirenDet/Edwards.lean` and `ZirenDet/FieldOp.lean`; produce it with
  `tools/gen_eddecompress.py <chip module file> <out>`.  Its `gadget_det` also determines the square
  root and its negation (the analyser takes those columns from the gadget), and the chip file needs
  `PICUS_BUDGET_S` above the 60 s default on a loaded machine (the analysis takes ~70 s).
- `KeccakSponge.lean` is produced by `tools/gen_keccak.py <chip module file> <out>` (8 MB, also
  generated by `../check/regen_all.sh`).  It lifts each typed step into a lemma and splits the rest of
  `gadget_det` into a chain of segment lemmas over `w`, `w'`: each takes the facts live at its
  start, projects the conjuncts it uses and ends by applying the next, so no declaration's context
  holds more than one segment.
- `top_postconditions.lean` holds hand-written proofs of the `postconditions` theorem of a chip's
  `top` module (`ShaCompress`, `MiscInstrs`, `Bls12381FpOpAssign`, `CloClz`, `AddSub`/`AddSubImm`,
  `DivRem`, `LoadNarrow`, `LoadWord`, `MemoryUnaligned`), where the generated proof runs out of its
  tactic budget and would be admitted; the generator uses a proof only
  when its statement is exactly the generated one.
